What it stops

  • Secrets in git. lint_secrets.py runs before a commit and fails on hard-coded Stripe, GitHub, AWS, Slack, OpenAI and Anthropic keys and private keys. It found a live Stripe secret in this store's own repo (below).
  • Instructions that point nowhere. lint_directives.py fails when CLAUDE.md or a directive references a script or directive that does not exist. It caught the kit's own CLAUDE.md doing that before release.
  • Risky shell commands, before they run. In Claude Code, the kit's guard_bash.py hook blocks a commit while the secrets linter finds a key, --no-verify, force-push, rm -r on /, ~ or the project root, and an ad-hoc pip install requests that never reaches requirements.txt. The agent sees why and what to do instead.
  • "Fixes" that only hide the failure. The bug-fix standard makes the agent name the root cause and add a test that fails before the fix (plus a written rule when it is a pattern); the operating principles treat a retry, reset or reprocess as recovery, never as the fix.

# claude -p, after the block:
A project hook (`hooks/guard_bash.py`) blocked `pip install requests`,
because a package installed ad hoc wouldn't be listed in a requirements
file and CI or prod would then break. Instead, I'd add `requests` with a
version pin to `requirements.txt` (or `pyproject.toml`) and run
`pip install -r requirements.txt`, which is what the hook asks for, or you
could set `AOK_ALLOW_ADHOC_PIP=1` if you really want a one-off install.

Why agents fail on real work

A model that's 90 % reliable per step is 59 % reliable over five steps. Real tasks are ten to fifty steps. If the agent executes everything itself — fetching, parsing, transforming, deploying — compounding error does the rest, and you end up watching it.

0.9⁵ = 59%agent does every step
0.9³ = 73%agent makes 3 decisions, scripts do the rest
→ 100%scripts + tests, once they work

D.O.E. moves everything with a right answer into tested code and leaves the agent exactly one job: deciding what to run next. Then it makes the system self-annealing — every failure becomes a test, a rule, and a lint, so month three is dramatically better than week one.

No. CLAUDE.md is the canonical file; Cursor users copy the three .mdc rules into .cursor/rules/; Codex and Gemini CLI users paste CLAUDE.md into AGENTS.md / GEMINI.md. The directives and scripts are tool-agnostic (plain Markdown and Python 3 scripts).

Why not just write my own CLAUDE.md?

You can, and the free plugin gives you ours to start from. A CLAUDE.md is only advice; the agent can ignore it. The paid kit is the part that checks: linters (with tests) that exit with an error, directives written after real incidents on a running business platform, and the loop that turns each failure into a test and a rule. Publish Gate v1: check AI-assisted posts before they go out

The gate this store's own agent runs before it posts anything. verify_post.py checks a draft against your facts.md and voice.md: stock AI phrases and your own banned list, numbers that are not in your facts file, dead links, checkout links without utm_source, then an LLM claim-by-claim check.
